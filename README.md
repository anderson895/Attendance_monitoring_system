# Attendance Monitoring System

A vanilla PHP attendance monitoring system built with the **MVC pattern**, **mysqli** (object-oriented), and **jQuery AJAX**. The codebase intentionally demonstrates the four pillars of OOP — **Abstraction, Encapsulation, Inheritance, Polymorphism**.

---

## Tech Stack

| Layer        | Technology                              |
|--------------|------------------------------------------|
| Backend      | Vanilla PHP 7.4+ (OOP)                   |
| Database     | MySQL via **mysqli** (NOT PDO)           |
| Frontend     | HTML5 + Centralized CSS                  |
| AJAX         | jQuery 3.7 (CDN)                         |
| Architecture | MVC + Front Controller + Singleton DB    |
| Server       | XAMPP (Apache + MySQL)                   |

---

## Features

### Admin
- Dashboard with live stats (total users, present today, late today, all-time records)
- Full users CRUD via AJAX (create, read, update, delete)
- Toggle role (`admin` / `user`) and account status (`active` / `inactive`)
- Attendance records with filters by **date range, user, status**
- Delete individual attendance records
- Cannot delete own admin account (safety check)

### User
- Live digital clock on the dashboard
- One-click **Time In / Time Out** via AJAX
- Auto-tags arrivals after 9:00 AM as `late`
- Personal attendance history with computed work durations
- Self-service profile update (name, email, password)

### Auth
- Session-based login/logout
- Self-registration creates `user`-role accounts
- Bcrypt password hashing (`password_hash` / `password_verify`)
- Inactive accounts blocked at login
- AJAX-only endpoints reject non-AJAX requests (`X-Requested-With` check)

## OOP Pillars — Where to Find Them

| Pillar          | File / Symbol                                              | What it does |
|-----------------|------------------------------------------------------------|--------------|
| **Abstraction** | `app/core/Model.php`                                       | `abstract class Model` declares `abstract create()` / `abstract update()`. Hides mysqli plumbing from children. |
| **Inheritance** | `app/models/User.php`, `app/models/Attendance.php`         | Both `extend Model` and reuse `findById()`, `delete()`, `all()`, `count()`. |
| **Encapsulation** | `User`, `Attendance`                                     | All fields `private`; mutated only through fluent setters (`setFullname()->setEmail()->...`) and read via getters. |
| **Polymorphism** | `User::create()` vs `Attendance::create()` (and `update()`) | Same abstract signature, different table-specific implementations. |

## Database Schema

Auto-generated by `install.php`.

| Column      | Type                                  | Notes                |
|-------------|---------------------------------------|----------------------|
| id          | INT AUTO_INCREMENT PK                 |                      |

### `attendance`
| Column      | Type                                          | Notes                                  |
|-------------|-----------------------------------------------|----------------------------------------|
| id          | INT AUTO_INCREMENT PK                         |                                        |
| user_id     | INT NOT NULL                                  | FK → `users.id` ON DELETE CASCADE      |
| date        | DATE NOT NULL                                 |                                        |
| time_in     | DATETIME NULL                                 |                                        |
| time_out    | DATETIME NULL                                 |                                        |
| status      | ENUM('present','late','absent') DEFAULT 'present' | `late` = time_in after 09:00       |
| remarks     | VARCHAR(255) NULL                             |                                        |
| created_at  | TIMESTAMP DEFAULT CURRENT_TIMESTAMP           |                                        |
| **UNIQUE**  | (`user_id`, `date`)                           | one record per user per day            |

## Installation

### 1. Prerequisites
- XAMPP (or any Apache + PHP 7.4+ + MySQL stack)
- Browser

### 2. Place the project
Copy the folder to:
```
C:\xampp\htdocs\attendance_monitoring_system\
```

### 3. Start services
Open the **XAMPP Control Panel** and start **Apache** and **MySQL**.

### 4. Run the installer (once)
Open in browser:
```
http://localhost/attendance_monitoring_system/install.php
```
This creates:
- Database `attendance_monitoring_system`
- Tables `users` and `attendance`
- Two seed accounts (see below)

### 5. Delete the installer (recommended)
After install, delete `install.php` so it can't be re-run.

### 6. Open the app
```
http://localhost/attendance_monitoring_system/
```

`.htaccess` rewrites pretty URLs into that form.

| `/admin/dashboard`                      | `AdminController::dashboard`                  |

## How AJAX is Wired

All dynamic interactions go through **`assets/js/app.js`** using jQuery's `$.ajax`.

```js
function ajaxPost(url, data) {
    return $.ajax({
        url: window.BASE_URL + url,
        type: 'POST',
        data: data,
        dataType: 'json',
        headers: { 'X-Requested-With': 'XMLHttpRequest' }
    });
}
```

On the PHP side, every AJAX endpoint calls `requireAjax()` which rejects requests missing the `X-Requested-With: XMLHttpRequest` header.

All responses follow the same shape:
```json
{ "status": "success" | "error", "message": "...", "data": ... }
```

## Security Notes

- **Prepared statements** on every query (`$stmt->bind_param(...)`)
- **Bcrypt** password hashing
- **Output escaping** with `htmlspecialchars()` and an `escapeHtml()` JS helper
- **Session role checks** via `requireLogin()` / `requireAdmin()` on the base controller
- **AJAX-only enforcement** via `X-Requested-With` header check
- **Self-deletion guard** — admins cannot delete their own account
- **Unique DB constraints** on username, email, and (user_id, date)

## Common Issues

**404 / "Object not found" on every page**
→ Apache `mod_rewrite` is disabled, or `.htaccess` is in the wrong folder. Enable `mod_rewrite` in `httpd.conf` and confirm `AllowOverride All` is set for `htdocs`.

**"Database connection failed"**
→ MySQL isn't running, or credentials in `app/config/config.php` are wrong.

**Pages load without styling**
→ `BASE_URL` mis-detected. The auto-detector assumes the project lives at `/attendance_monitoring_system/`. If you renamed the folder, update `RewriteBase` in `.htaccess`.

**"AJAX requests only" returned for a page**
→ You navigated directly to an AJAX endpoint. AJAX endpoints (`doLogin`, `listUsers`, `timeIn`, etc.) only respond to XHR requests — they're called by `app.js`, not opened in the browser.
